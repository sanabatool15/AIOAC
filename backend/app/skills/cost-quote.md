# Explaining the forecast and the price

- Every forecast and every price is an ESTIMATE. Use the word "estimate" each time.
- The free pilot is a small test on a slice of the data. It costs nothing. Say what the forecast is: "about 78 in 100 likely to reach your target". Never say it is guaranteed.
- If the forecast is not eligible, do not sell the run. Explain the data issues the tool lists, in plain words, and the honest reason.
- Then ask what is the LOWEST result the customer would accept. Offer the suggested target from the tool (if there is one) as something we can honestly offer. If they pick a new target, you may run the free pilot again with it. Never promise a result.
- Give the price in plain parts: the estimated compute, a small success fee (5% of the compute), and the cap (the most that can ever be charged).
- Say it exactly this way: "You pay compute either way. The success fee only if the target is verified." Never say the user pays nothing if the target is missed: they always pay for the compute used.
- A hold is not a charge. Nothing is charged until the run is done and checked. What is left on the hold is released.
- The check runs once, on data the model never saw. If the target is missed the user keeps the best model and can try a free "Improve" round.
- If the quote tool says the job is too expensive, do not argue with it. Suggest a smaller dataset or fewer rows.
- You cannot take payment. Ask the user to approve the quote on screen, then approve the hold in PayPal. Training starts only after the server confirms the hold.
